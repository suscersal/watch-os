# BLE-мост: часы <-> телефон

Зачем: в школьной сети с входом через Госуслуги часы сами в интернет не выйдут. Телефон уже в сети
(вошёл сам), поэтому часы просят его выполнить запрос и вернуть ответ по Bluetooth LE.

Решение: **ключ API ИИ хранится на телефоне, а не на часах.** Часы шлют только текст запроса. Так ключ не
вытащить из прошивки, и приложение на часах не может его украсть.

Статус: это спецификация. Реализации ещё нет (ни на часах, ни в Android-приложении).

## Роли

- Часы: BLE-периферия (GATT-сервер), рекламируют сервис и ждут подключения.
- Телефон: приложение для Android (центральное устройство), подключается к часам, выполняет запросы.

На часах транспорт выбирается автоматически: есть Wi-Fi с интернетом -> `esp_http_client`, нет -> BLE-мост.
Для `net_get()` и для `ai.ask*` ядро не меняется: транспорт прячется за `net_get()` и новым `ai_ask()`.

## GATT

| | UUID | Свойства | Направление |
|---|---|---|---|
| Сервис | `6936cf0c-04fd-42ef-a86c-6a894a6a99b3` | | |
| `TO_PHONE` | `7a7866e2-7f19-4f90-987c-afe9d5bec973` | Notify | часы -> телефон |
| `FROM_PHONE` | `fc8ad735-575c-40a2-86b6-7a81749be01c` | Write, Write Without Response | телефон -> часы |

Обе характеристики требуют шифрования с аутентификацией (см. «Безопасность»). MTU: телефон запрашивает 247,
часы принимают; полезная нагрузка пакета = MTU - 3.

## Кадры

Сообщение передаётся потоком байт, который режется на пакеты по размеру MTU. Порядок гарантирует BLE.
Приёмник собирает кадры из потока по заголовку.

```
offset size  поле
0      1     magic = 0x57 ('W')
1      1     version = 1
2      1     type
3      2     id      (u16 LE) - номер запроса, ответ повторяет его
5      4     len     (u32 LE) - длина payload, не больше 65536
9      len   payload
```

Если magic не совпал или len больше лимита, приёмник сбрасывает буфер и ждёт следующий magic;
часы при этом могут отправить `ERR` с id=0. Незавершённый кадр сбрасывается через 10 секунд.

| type | имя | направление | payload |
|---|---|---|---|
| 0x01 | `HELLO` | оба | JSON `{"v":1,"name":"...","max_payload":65536}` |
| 0x02 | `PING` / 0x03 `PONG` | оба | пусто |
| 0x10 | `REQUEST` | часы -> телефон | JSON запроса (ниже) |
| 0x11 | `RESPONSE` | телефон -> часы | тело ответа (байты) |
| 0x12 | `ERROR` | телефон -> часы | UTF-8 текст ошибки для показа на экране (до 120 байт) |
| 0x13 | `CANCEL` | часы -> телефон | пусто, id запроса, который нужно прервать |

Одновременно выполняется один запрос (часы ждут ответ синхронно, как сейчас делает `net_get`).
Таймаут часов: 30 секунд на запрос. При обрыве связи запрос считается неудавшимся.

## Запросы (`REQUEST`)

HTTP GET (для установщика приложений и `net.get`):
```json
{"op": "get", "url": "https://example.com/app/manifest.json", "max": 16384}
```
Ответ: `RESPONSE` с телом при статусе 200, иначе `ERROR` («HTTP 404» и т.п.).

Вопрос к ИИ:
```json
{"op": "ai", "prompt": "Столица Австрии?", "format": "text", "lang": "ru"}
{"op": "ai", "prompt": "Планеты солнечной системы", "format": "table", "lang": "ru"}
```
- `format: "text"`: ответ короткий, обычный текст UTF-8 (телефон просит модель отвечать в 1-3 предложения).
- `format: "table"`: ответ строго JSON `{"rows": [[...], ...]}`: не больше 4 колонок и 16 строк, ячейка до 47 байт
  (под лимиты `tables.h`). Телефон проверяет JSON перед отправкой; если модель вернула мусор, повторяет запрос
  один раз, потом шлёт `ERROR`.

Новые операции добавляются полем `op`; неизвестный `op` -> `ERROR "unsupported"`.

## Безопасность

Телефон выполняет запросы по просьбе устройства, поэтому мост нужно защищать с обеих сторон.

Подключение:
- LE Secure Connections с проверкой кода: часы показывают 6-значный код на экране, пользователь вводит его на
  телефоне (Passkey Entry). Устройство запоминается (bonding), повторно код не нужен.
- Характеристики доступны только для зашифрованного и аутентифицированного соединения; по открытому соединению
  часы ничего не отдают.
- Подключается только одно запомненное устройство; новое сопряжение запускается вручную в «Настройках» часов.

Телефон (Android-приложение) обязан:
- выполнять только `http://` и `https://`; редиректы только на `https://`, не больше 3;
- блокировать адреса локальной сети, loopback и link-local (192.168.*, 10.*, 172.16-31.*, 127.*, 169.254.*, localhost,
  а также имена, которые резолвятся в такие адреса): приложение на часах не должно сканировать школьную сеть через телефон;
- ограничивать размер ответа (`max`, не больше 65536) и время запроса (10 с);
- хранить ключ API в Android Keystore / EncryptedSharedPreferences и никогда не отдавать часам;
- показывать в уведомлении, что мост активен, и вести журнал запросов (адрес, время, размер) с кнопкой «Очистить»;
- иметь список разрешённых доменов и режим «спрашивать при новом домене» (по умолчанию включён).

Часы:
- разрешения приложений (`net`, `ai`) по-прежнему проверяются на часах до отправки запроса в мост;
- текст запроса к ИИ не логируется.

## Android-приложение (план)

- Kotlin, один экран: статус подключения, поле для ключа API и выбор модели, список разрешённых доменов, журнал.
- Foreground service с типом `connectedDevice`, поддерживает соединение и переподключается к запомненным часам.
- Разрешения Android 12+: `BLUETOOTH_SCAN`, `BLUETOOTH_CONNECT`; для Android 11 и ниже ещё геолокация (требование сканирования BLE).
- HTTP: OkHttp. BLE: системный `BluetoothGatt`.
- Сервис ИИ: настраиваемый адрес и формат запроса (по умолчанию Anthropic Messages API).

## Сторона часов (план)

- `esp32/main/net_ble.c`: GATT-сервер на NimBLE (компонент `bt` в ESP-IDF), сборка и разбор кадров, `net_ble_get()`.
- В `net_esp.c`: если Wi-Fi не подключён, `net_get()` пробует мост.
- Новый интерфейс ядра `ai.h`: `char *ai_ask(prompt, format, err, errn)`; на ESP32 идёт в мост (или напрямую по Wi-Fi, если ключ
  задан на часах); на ПК - прямой HTTPS-запрос с ключом из окружения. Системные вызовы `ai.ask` и `ai.ask_table`
  переходят с заглушки на `ai_ask()`.
- Экран «Настройки -> Телефон»: сопряжение, код, состояние связи, «Забыть телефон».
- Нагрузка на радио: BLE и Wi-Fi делят антенну ESP32-S3, возможны задержки при одновременной работе.
