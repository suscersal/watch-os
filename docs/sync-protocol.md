# Протокол синхронизации часов (версия 1)

Телефон или компьютер передают на часы фото и время. Часы принимают соединение, только пока открыт экран **Sync**,
и требуют одноразовый 6-значный код с этого экрана.

Транспорт сейчас TCP по Wi-Fi (порт 8765). Протокол не зависит от транспорта, так что тот же поток байт можно
пустить по BLE (см. `ble-bridge.md`).

## Кадры

```
[тип: 1 байт][длина: 4 байта, little-endian][данные]
```
Данные одного кадра не больше 20000 байт. Все числа little-endian.

### Телефон -> часы

| Тип | Имя | Данные |
|---|---|---|
| 0x01 | HELLO | версия u8 (=1), код 6 ASCII-цифр, имя устройства (utf-8, до 32 байт) |
| 0x02 | TIME | epoch (UTC) i64, смещение пояса в минутах i16 |
| 0x10 | PHOTO_BEGIN | id u32, снято (epoch) u32, размер миниатюры u32, размер фото u32, crc32 u32 (от миниатюры+фото подряд) |
| 0x11 | PHOTO_DATA | сырые байты: сначала миниатюра, потом полный кадр; куски до 16384 байт |
| 0x12 | PHOTO_END | пусто |
| 0x13 | PHOTO_LIST | пусто |
| 0x14 | PHOTO_DELETE | id u32 |
| 0x30 | AUDIO_BEGIN | id u32, размер u32, crc32 u32 (всего файла), name_len u8, имя (utf-8, `.wav`). Ответ OK: 0 - слать, 1 - такой файл уже есть |
| 0x33 | AUDIO_COVER | необязательно, сразу после AUDIO_BEGIN: обложка, baseline JFIF JPEG до 160x160, не больше 20000 байт. Хранится как `<имя>.jpg` рядом с треком |
| 0x31 | AUDIO_DATA | сырые байты WAV (PCM), куски до 16384 байт; пишутся на диск по мере прихода |
| 0x32 | AUDIO_END | пусто; проверяются размер, crc32 и заголовок WAV |
| 0x20 | MESSAGE | уведомление: `id u32, ts u32, app_len u8, title_len u8, text_len u16`, затем `app, title, text` (utf-8; не больше 32 / 64 / 256 байт). Тот же `id` заменяет прежнее уведомление. Ответ OK |
| 0x7F | BYE | пусто |

### Часы -> телефон

| Тип | Имя | Данные |
|---|---|---|
| 0x80 | OK | запрос u8, статус u8 (для PHOTO_BEGIN: 0 - слать данные, 1 - такое фото уже есть) |
| 0x81 | HELLO_OK | версия u8, фото на часах u16, максимум фото u16, максимум байт полного кадра u32 |
| 0x91 | LIST | число u16, затем id u32 (новые первыми, не больше 200) |
| 0x8F | ERR | запрос u8, код u8 |

Коды ошибок: 1 плохой кадр, 2 неверный код, 3 команда не к месту, 4 слишком большое, 5 не сошёлся crc32,
6 формат картинки не подходит, 7 нет места (максимум 100 фото), 8 не поддерживается, 9 часы заблокированы PIN.

## Сеанс

1. HELLO с кодом. После трёх неверных кодов часы разрывают соединение. Любая другая команда до HELLO - ошибка и разрыв.
2. TIME (по желанию), PHOTO_LIST (чтобы не слать то, что уже есть).
3. На каждое фото: PHOTO_BEGIN (ответ OK/0 или OK/1), PHOTO_DATA кусками, PHOTO_END (ответ OK или ошибка).
4. BYE.

Пока часы заблокированы PIN-кодом, любая команда получает ошибку 9 и соединение закрывается.

## Требования к картинкам

Часы показывают JPEG через декодер LVGL TJpgDec, поэтому:

- **baseline JPEG** (прогрессивные не читаются) с заголовком **JFIF** (`FF D8 FF E0 00 10 'J' 'F' 'I' 'F'`);
- полный кадр не больше **410x502** (вписать с сохранением пропорций, не увеличивая), не больше 256 КБ;
- миниатюра не больше **160x160** (приложения делают квадрат 120x120), не больше 32 КБ.

Нарушение даёт ошибку 6 при PHOTO_END, фото не сохраняется.

`id` фото выбирает отправитель; приложения берут CRC32 исходного файла, поэтому повторная отправка
ничего не дублирует. Файлы на часах: `data/photos/<снято hex8>_<id hex8>.jpg` и `.t.jpg`.

## Безопасность

- приём включён только пока открыт экран Sync, код одноразовый и меняется при каждом открытии;
- трафик **не шифруется**: годится для домашней сети. TLS и постоянное сопряжение (ключи) - следующий шаг;
- чужие программы на часах доступа к этой папке не имеют (у JSON-приложений нет файловых вызовов).

## Постоянный код для уведомлений (добавлено)

Кроме одноразового кода с экрана Sync у часов есть постоянный 6-значный код (Settings > Notifications). Пока переключатель включён, часы слушают порт
в фоне. Сессия, открытая постоянным кодом, ограничена: разрешены только HELLO, TIME, MESSAGE и BYE, остальное получает ошибку 10 (`not allowed with this code`,
соединение остаётся). HELLO_OK для такой сессии сообщает 0 фото. Такая сессия работает и при блокировке PIN (сообщение сохраняется, текст на экране блокировки не
показывается), а одноразовый код при блокировке по-прежнему отвечает ошибкой 9 и закрывает соединение. Клиент молчащий дольше 20 секунд отключается.
Сопряжение: ссылка `watchsync://pair?host=<ip>&port=<порт>&code=<код>[&mode=notify]` (она же в QR-кодах на экранах Sync и Notifications).
Передача идёт открытым текстом по локальной сети; постоянный код можно подсмотреть в трафике, поэтому доступ ограничен безобидными командами, а код
меняется кнопкой "New code".
